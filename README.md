# scaner

Сканер безопасности сайтов малого бизнеса: вводишь домен — получаешь понятный отчёт
о проблемах, чем они грозят и как их исправить.

Сейчас доступны CLI и внутренний gRPC-сервис с проверками TLS-сертификата и
протокола, перенаправления HTTP на HTTPS, HTTP-заголовков, сессионных cookies,
известных открытых файлов и каталогов, административных форм, почтовых
TXT-записей (SPF, DMARC, DKIM), пассивное определение CMS и ограниченная
проверка TCP-портов. Шаблоны Nuclei требуют отдельной оценки безопасного набора;
API может получать результаты через потоковый gRPC-сервис.

> ⚠️ Только неинвазивные проверки. Сканируйте только свои домены или домены,
> владелец которых дал согласие.

## Быстрый старт

Нужен Go 1.24+ ([установка](https://go.dev/dl/)).

```bash
git clone https://github.com/z1kkky/scaner.git
cd scaner

# запустить без сборки
go run ./cmd/scanner example.com

# с другим таймаутом на каждую проверку (по умолчанию 10s)
go run ./cmd/scanner -timeout 20s example.com

# собрать бинарник и запустить его
go build -o scanner ./cmd/scanner
./scanner example.com

# тесты
go test ./...
```

Можно передать и URL целиком (`https://example.com/page`) — сканер сам оставит домен.

### Необязательные проверки Nuclei

Nuclei запускается только при явном флаге `-nuclei`; без него набор проверок
не меняется. Нужен отдельно установленный исполняемый файл `nuclei`. Сканер
передаёт ему только встроенный набор из двух HTTP GET-шаблонов (публичный
`.git/HEAD` и Apache `/server-status`), не загружает upstream-шаблоны и отключает
обновления. Ограничения запуска: 1 шаблон одновременно, 2 запроса в секунду,
таймаут запроса 5 секунд, собственный предел категории 20 секунд (также
ограниченный общим `-timeout`, по умолчанию 10 секунд) и лимит вывода 1 МиБ.
Сырые запросы и ответы не сохраняются.

```bash
go run ./cmd/scanner -nuclei example.com
```

Флаг действует только в CLI. Nuclei пока не включён в gRPC daemon: внешний
процесс требует отдельной защиты от DNS rebinding и доступа к непубличным
адресам. Сканируйте только цели с явным разрешением.

## Внутренний gRPC-сервис

```bash
go run ./cmd/scannerd -listen 127.0.0.1:50051 -timeout 10s
```

По умолчанию daemon отказывается слушать адрес вне loopback. Удалённый listener
требует явный `-allow-remote` и mTLS: `-tls-cert`, `-tls-key` и `-client-ca`.
Loopback-режим предназначен для локального доверенного API. HTTP-проверки daemon
подключаются только к публичным IP-адресам: DNS проверяется непосредственно
перед соединением, а соединение устанавливается с проверенным адресом.
На один daemon разрешено до 8 одновременных сканов; при остановке он ждёт
завершения потоков до 15 секунд, затем принудительно закрывает соединения.
Реализован стандартный gRPC health service.

`ScannerService.StartScan` принимает `scan_id` и каноническое имя домена
без схемы, порта и пути. Возвращает `started`, результаты категорий по мере
готовности и `finished`; последовательность начинается с 1. Пустой `checks`
выбирает реализованные категории. Известная, но ещё не реализованная категория
возвращает `SKIPPED`. Неизвестные enum и некорректные параметры
отклоняются с `InvalidArgument`. При разрыве потока проверки отменяются.
Повторного воспроизведения событий пока нет.

### Оценка

Итоговая оценка — эвристика, а не сертификация безопасности или гарантия
отсутствия уязвимостей. Она рассчитывается только если запрошены и полностью
завершены все реализованные категории; при частичном результате, ошибке,
неизвестной серьёзности или запросе только части категорий `score` отсутствует.
За каждую уникальную находку вычитается 5 баллов за `low`, 10 за `medium`, 20
за `high` и 35 за `critical`; `info` баллы не снижает. Повтор одной и той же
находки на нескольких страницах не суммируется. Результат ограничен диапазоном
0–100: A (90–100), B (80–89), C (70–79), D (60–69), E (50–59), F (0–49).
Если DKIM-селекторы не переданы, email-проверка неполна, поэтому оценка не
выдаётся: передайте известные селекторы, чтобы получить полный результат.

Сервис предназначен для вызовов доверенного API в закрытой сети. Проверку
владения доменом выполняет API; у gRPC-сервиса пока нет аутентификации.
Каждая реализованная проверка заполняет `probes`, в том числе для чистых,
пропущенных и неудачных подпроб. Находки содержат `id`, `probe_id`, `probe`,
`location`, `evidence`. Значения cookies и полные DNS-ответы в evidence не попадают.

`page_paths` добавляет страницы к `/` (до 20 путей); проверка использует HTTPS
и не следует редиректам. Разрешены только пути того же источника, например
`/login`. Идентификаторы проб включают путь; повторные пути убираются.
Сессионные cookies распознаются по известным именам (`sessionid`, `PHPSESSID`,
`JSESSIONID` и другим). Если их нет, подпроба пропускается как неприменимая.

`dkim_selectors` задаёт до 20 известных селекторов для DNS-запросов
`selector._domainkey.domain`. Если селектор неизвестен, DKIM получает `SKIPPED`,
а почтовая категория — `INCOMPLETE`. Проверяются наличие/единственность записей,
базовая политика SPF/DMARC, наличие и кодировка ключа DKIM. Это проверка DNS-конфигурации,
а не верификация подписи письма. SPF include/redirect не разворачиваются,
DMARC не ищется на родительском домене; redirect без all отмечается `INCOMPLETE`.
Правила основаны на [RFC 6376](https://www.rfc-editor.org/rfc/rfc6376.html) и
[RFC 7208](https://www.rfc-editor.org/rfc/rfc7208.html).

TLS-проверка оценивает срок действия и имя сертификата, доверенную цепочку,
согласованную версию протокола и перенаправление HTTP на HTTPS для того же
домена. TLS 1.0 и 1.1 считаются устаревшими. Для сертификата проверяется
текущее системное хранилище доверенных корней; сетевые ошибки остаются статусом
подпробы, а не находкой об уязвимости.

Проверка exposures обращается только к фиксированному списку путей для Git,
`.env`, резервных копий, листинга каталогов и административных форм. Не более
четырёх запросов выполняются одновременно; каждый ограничен таймаутом и чтением
первых 4 KiB ответа. Перенаправления не выполняются, содержимое ответов не
попадает в отчёт.

CMS определяется пассивно по заголовку `X-Generator`, HTML-тегу `generator`
и характерным маркерам WordPress, Drupal, Joomla или Magento на главной HTTPS-
странице. Читается не более 8 KiB HTML, редиректы не выполняются; сообщённая
версия носит информационный характер и не является заключением об уязвимости.

Проверка портов подключается только к TCP-портам 21, 22, 23, 25, 3306, 5432,
6379, 8080, 8443 и 9200 и сразу закрывает соединение, не отправляя прикладных
данных. Она не сканирует диапазоны; таймаут/фильтрация не считаются открытым
портом.

Сетевая ошибка помечает подпробу `FAILED` и не создаёт находку об уязвимости.
При частичном выполнении сохраняются уже полученные результаты; категория
получает `INCOMPLETE`, а итог скана — `PARTIAL`.

Сгенерированные Go-файлы лежат рядом с `api/scanner/v1/scanner.proto`.
Для повторной генерации нужен `protoc` с поддержкой proto3 optional:

```bash
go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.36.6
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@v1.5.1
export PATH="$(go env GOPATH)/bin:$PATH"
protoc -I . --go_out=. --go_opt=paths=source_relative \
  --go-grpc_out=. --go-grpc_opt=paths=source_relative \
  api/scanner/v1/scanner.proto
```

## Локальный веб-прототип

Веб-консоль доступна только по loopback-адресу. Соберите и запустите её:

```bash
go build -o scannerweb ./cmd/scannerweb
./scannerweb
```

Откройте <http://127.0.0.1:8787>. По умолчанию цели и история хранятся в
`os.UserConfigDir()/scaner/local/state.json` (в Linux обычно
`~/.config/scaner/local/state.json`). Другой каталог можно указать флагом
`-data /путь/к/каталогу`. Удалите отдельную задачу кнопкой в истории; удаление
цели также удаляет связанные с ней задачи и результаты.

Кнопка демо сохраняет детерминированный примерный отчёт с явной пометкой
«имитация» и не вызывает DNS, сканер или сетевые проверки. Для реального
сканирования добавьте домен, разместите показанную TXT-запись, подтвердите её,
задайте только нужные поддомены (если они нужны) и порты. Перед каждым запуском
оператор должен отдельно подтвердить наличие письменного разрешения; сервис
сохраняет эту аттестацию с задачей. TXT подтверждает контроль DNS, но не право
на тестирование. Поиск поддоменов и произвольные шаблоны не поддерживаются.

Живой Nuclei-запуск требует Linux, Docker CLI с доступным daemon и бинарник
Nuclei v3.11.1 по пути `nuclei/nuclei` (или путь к бинарнику через `-nuclei`).
Сервис проверяет версию и SHA-256 бинарника, а при первом живом запуске собирает
контейнер на закреплённом Ubuntu image digest; для контейнера используется
отдельная сетевая изоляция и шлюз области цели. Если бинарник, Docker или сборка
контейнера недоступны, задача завершается ошибкой, а не отчётом об отсутствии
находок. Демо при этом остаётся доступным без Docker.

Это локальный прототип, не предназначенный для публичного развёртывания или
production-использования. Веб-поток реального сканирования во время разработки
не запускался на публичных целях.

## Структура

```
cmd/scanner/main.go        точка входа: разбор аргументов, запуск, вывод JSON
internal/check/check.go    интерфейс Check и структура Finding
internal/check/headers.go  проверка заголовков HSTS, CSP, X-Frame-Options, X-Content-Type-Options
internal/check/tls.go      проверка сертификата, протокола TLS и HTTP→HTTPS
internal/check/exposures.go проверка фиксированных чувствительных путей
internal/check/cms.go      пассивное определение CMS
internal/check/ports.go    ограниченные TCP-проверки allowlist-портов
internal/runner/runner.go  параллельный запуск проверок в горутинах с таймаутами
```

`internal/` — особая папка в Go: её пакеты можно импортировать только внутри этого репозитория.

## Локальная интеграционная лаборатория

Практический прогон всех встроенных категорий на управляемой loopback-цели:

```bash
go test ./internal/check -run '^TestScannerLab$' -v
```

Тест поднимает локальные HTTP/TLS fixtures, моделирует открытый TCP-порт и DNS
TXT-записи; наружу запросы не отправляются. Он проверяет ожидаемые находки и
отсутствие утечки тестового секрета в отчёт.

## Как добавить новую проверку

1. Создайте файл в `internal/check/`, например `exposures.go`.
2. Объявите тип и два метода — `Name() string` и `Run(ctx, domain) ([]Finding, error)`.
   Этого достаточно, чтобы тип подходил под интерфейс `Check`.
3. Передавайте `ctx` во все сетевые вызовы — так сработает таймаут.
4. Зарегистрируйте проверку в `internal/check/defaults.go`, чтобы CLI и daemon
   использовали один набор. Для подробных результатов реализуйте `RunDetailed`,
   для параметров запроса — `WithOptions`.
5. Напишите тест рядом (`tls_test.go`) и запустите `go test ./...`.
